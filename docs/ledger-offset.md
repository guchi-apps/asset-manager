# 家計簿の収入の相殺（Issue #1343）

現金収入を先に「収入」で記録したあと、実際は現金を受け取らず別の口座（カード・銀行など）で支払い済みだったと
分かったときに、その収入を振替へ置き換える。

- 入口: 収入の編集ダイアログの「他の手段で相殺（振替にする）」。相殺先の口座を選んで実行する
- 結果: 同じ取引が `TRANSFER`（振替元＝元の入金先、振替先＝相殺先）に変わる。収入は収支・カテゴリ別から外れる
- 振替は種類として常に収支から除外される。取引明細では「集計に含めない」のバッジフラグの有無によらず振替に付ける（#1391）。フラグが影響するのは「貯蓄・投資へ」の計上だけ
- 実装: `lib/ledger-offset.ts` の `buildOffsetTransfer` が更新の入力を作り、`updateEntryAction` を**1回**呼ぶ。
  新規作成＋削除に分けると片方だけ成功する経路ができるため、分けない
- メモには「収入から相殺（元の収入: N円）」を足す。専用の紐付けカラムは持たない（スキーマ変更なし）
- 元に戻すときは、通常の編集で種別を収入へ戻す

## 収入と支出（振替）を1件の振替にまとめる（Issue #1368）

現金を受け取って（収入）同じ額を銀行から払った（支出）とき、あるいは手で入れた現金の収入と、取り込んだ「銀行→財布」の振替が
二重になっているときに、2件を1件の振替へまとめる。

- 入口: 収入・支出の編集ダイアログの「取引とまとめる（振替にする）」。同額・日付の差が7日以内・確定済みの相手が候補に出る（最大5件）
  - 収入から: 入金先と別の口座から出た支出、または入金先と同じ口座へ入る振替
  - 支出から: 出金元と別の口座へ入った収入
  - 品目が2件以上・立て替え・分割払い・後払い・按分・返金の紐づけがある取引は対象外
- 結果: 「出金元 → 収入の入金先」の振替1件（日付はお金が出た側）。振替が相手なら振替を残して収入を消す。支出が相手なら取り込んだ行を残す
  （手入力どうしなら支出の行）。消した取り込み行は `deleteEntryInTx` が明細を `DISMISSED` にするので再取り込みされない
- 振替は「集計に含めない」を外す（上の相殺・#822 の振替ルールと揃える）。メモは両方を残し、まとめた旨を1行足す
- 実装: 判定は `lib/ledger-merge.ts`、書き込みは `lib/ledger-service.ts` の `mergeEntriesToTransfer`。残す行の書き換えは
  `updateEntry` と同じ `writeEntryUpdateInTx` を通すので、取り込んだ行なら手直しの記録（`editedFields`）が残り、再同期で元に戻らない。
  書き換えと削除は1トランザクション
- 取り込み時の自動の統合はしない。偶然の同額で黙って行を消す危険があるため

### #1368 の事例が振替になった理由

アプリ側に「既存の収入と組にして振替へ変える」処理は無い。Zaimの明細そのものが「振替 VNEO代表口座 → 財布・集計に含めない」
（`mode = transfer`、`calc_flag = 0`）で、取り込みはそれを写しただけ（`lib/ledger-sources/zaim/adapter.ts` の `resolveZaimKind`）。
分類ルール（#822 `TRANSFER_TO`）で振替にした場合は「集計に含めない」が外れるので見分けられる。Zaimの口座連携が、友人への振込を
財布への引き出しと判定したとみられる。結果として財布に収入と振替の両方で同じ2万円が入っていたので、上の「まとめる」で収入を消す。
