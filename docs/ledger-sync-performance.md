# 家計簿の明細取り込みの速さ（Issue #1090）

家計簿の取り込み（`lib/ledger-sources/sync-service.ts` の `syncSourceSnapshotLocked`）は、AIDEが返す
**当月＋前月の明細を毎回すべて**受け取る（差分ではない）。届いた明細の大半は前回と同じ内容なので、
**明細1件ごとにDBへ問い合わせる書き方をすると、変化が無いだけの明細で件数に比例して遅くなる。**

## いまの書き方

- ループで使う読み込み（取引が残っているか・手直しした項目・レシートの有無）は、ループの前にまとめて引く
- 前回と同じ内容（`payloadHash` が同じ）の記録は、ループの中では書かず、更新先ごとに id を集めて
  最後に `updateMany` で書く（`unchangedTouchOf`）。「見当たらない」にする記録も同じ
- 「見当たらない」の候補は、全日を読めた月（`coveredMonths`）の範囲だけを読む（`coveredDateRange`）。
  取り込み開始日以降の全期間を読むと、履歴が増えるほど重くなる
- 取引の作成・更新は従来どおり1件ずつのトランザクション（#830 の二重登録の防波堤）。新しい明細・変わった明細は
  毎回数十件程度なので、ここは一括にしていない
- 「今すぐ取り込む」と定期実行（`scripts/ledger-sync.ts`）は、家計簿の取り込みで読んだAIDEの応答
  （`ZaimLedgerSyncResult.aidePayload`）をスマートレシート・Amazonの取り込みへ渡し、同じ一覧を2回取りに行かない

**ループの中に `await prisma...` を足すときは、件数ぶん往復しないかを先に考える。**

## 実測（ローカルDB・合成データ3,000件）

| 場面 | 変更前 | 変更後 |
|---|---|---|
| 変化なし（毎回の大半） | 13,960ms・18,026クエリ | 351ms・40クエリ |
| 100件変更・100件消失・20件復活 | 14,990ms・18,955クエリ | 1,584ms・1,650クエリ |
| 初回（3,000件すべて追加） | 27,287ms | 26,718ms（変えていない） |

変更前後で、取り込み後の記録・取引の状態と件数（追加・更新・要確認・見当たらない・復帰）が一致することを確かめた。
所要時間はサーバーログに `[ledger-sync] … 明細N件をXmsで反映` として出る。

## AIDEから必要な分だけ取る（Issue #1098）

AIDE#785 で `GET /api/money/transactions` が ETag/304・`?from=`・鮮度ヘッダー（`X-AIDE-Stale` など）・gzip に対応した。
asset-manager側の使い方は次のとおり。

- **定期実行（`scripts/ledger-sync.ts`）だけが前回のETagを `If-None-Match` で送る。** 304なら家計簿の取り込みを見送る
  （実行記録には「AIDEの巡回が前回の取り込みから変わっていない」と残す）。「今すぐ取り込む」は常に全件を取る
- **304でも `X-AIDE-Stale: true` なら本文を取り直して従来の判定へ戻す**（鮮度の判定を誤らせない）
- **ETagを保存するのは、家計簿が `SUCCESS` で、スマートレシート・Amazonの取り込みも成功したときだけ**（`User.ledgerSourceEtag`）。
  `PARTIAL`・`SKIPPED`・`FAILED`、リンク側の失敗で保存すると、次回が304で見送られて再試行されない
- **取り込みの結果は口座・カテゴリの対応と取り込み開始日にも依存する。** それらを書く口は
  `invalidateLedgerSourceEtag`（`lib/ledger-sources/etag.ts`）でETagを破棄する（開始日・対応の保存、口座とカテゴリの削除・統合、
  家計簿の初期化、カテゴリ対応の一括取り込み、CSV取り込みと取り消し）。**新しくこれらを書く口を足したら、ここも呼ぶ。**
  取りこぼしの保険として、ETagは保存から24時間で無効になり、1日1回は必ず全件を取る
- スマートレシート・Amazonの取り込みは、家計簿の取り込みの応答（200）があれば使い回し、無い（304で見送った）ときは
  読む日数ぶん（60日）だけを `?from=` で取る。`months` は月まるごと入る月だけになるので、**期間指定の応答では
  「見当たらない」の判定をしない**（その判定は家計簿の取り込み＝全件取得だけが行う）
- gzipはNodeのfetchが `Accept-Encoding` を送って自動で展開するので、こちらの実装は無い
- `?since=` の差分取得はAIDE側が見送ったため使っていない
