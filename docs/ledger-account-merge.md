# 家計簿の口座の結合（#973）

二重に作ってしまった口座などを1つにまとめる機能。口座の「編集」ダイアログの「この口座の操作」にある
「別の口座へ結合」から、結合先を選んで実行する。結合元の口座名を入力するまで実行できない（取り消せない操作のため）。

## 何が起きるか

| 対象 | 扱い |
|---|---|
| 結合元が出金元・入金先の取引 | 結合先へ付け替える |
| 結合元と結合先のあいだの振替 | 同じ口座どうしになるので取引ごと消す（品目・立て替え・支払いも消し、取り込み元の明細は `DISMISSED` にして作り直さない。削除と同じ `deleteEntriesInTx`） |
| 分けた支払い（`LedgerPayment`。#944） | 結合元の行を結合先へ付け替える。結合先の行もあれば合算し、1行になったら分けるのをやめて出金元だけで持つ |
| 取り込み元の口座名の対応（`LedgerSourceAccountMapping`） | 結合先へ移す（以後の取り込みは結合先に入る） |
| 振替ルール（`LedgerClassificationRule.accountId`） | 結合先へ移す |
| レシート・サブスクの支払い口座（`ReceiptImport.ledgerAccountId`・`SubscriptionPaymentMethod.ledgerAccountId`） | 結合先へ移す |
| 結合先の設定（種類・用途・反映のしかた・色・基準日など） | そのまま残す |
| 結合元の口座 | 削除する |

## 初期残高の決め直し

結合の前後で「2口座の残高（全期間）の合計」が変わらないよう、結合先の初期残高を決め直す（基準日は結合先のまま）。
結合元の基準日が結合先より早いと、結合先の基準日より前の結合元の取引は結合後に数えなくなり、逆に遅いと、結合元で
数えていなかった取引を数え始める。その差と、消した振替の分を初期残高で吸収する。計算は `lib/ledger-account-merge.ts` の
`planAccountMerge`（結合後の取引で結合先の残高を数え直し、合計との差を初期残高にする）。

## 排他

削除（`deleteAccount`。#899・#917）と同じく、取り込み中の印（`acquireLedgerSyncLock`）を取ってから、両方の口座の行に
id の順で排他ロックを取り、対象の取引を `FOR UPDATE` で読んでから付け替える。最後に結合元を指す取引が残っていないことを
確かめてから結合元を消す。実装は `lib/ledger-service.ts` の `mergeAccount`。

## 注意

- 結合元と結合先が別々のZaim口座に対応していると、結合先に2つのZaim口座名が対応する。Zaimの残高（#881）は
  対応が1つに定まらない口座には出さない（`matchExternalBalances`）ため、結合先にZaimの残高が出なくなる
- 結合を取り消す機能は無い
