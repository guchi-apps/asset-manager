# カードの引き落とし口座の残高確認（#1141）

カード口座（`LedgerAccount`）に「締め日・引き落とし日・引き落とし月・引き落とし口座」を持たせ、
今後30日の引き落としに対して引き落とし口座の残高が足りるかをホームに出す。実装は
`lib/ledger-card-withdrawal.ts`（純関数）・`lib/ledger-card-withdrawal-service.ts`（DB読み込み）・
`components/dashboard/card-withdrawal-banner.tsx`。

## 値の取り方
- **手入力**（口座の編集 → 「引き落とし（残高確認）」）。3つ（締め日・引き落とし日・引き落とし口座）がそろったカードだけが対象
- Zaim公式APIは終了し（#788）、AIDEの連携が返す項目にも締め日・支払日は無い。取得できるかの調査は #1149（下記）

## Zaimから取れるか（#1149 の調査結果。2026-11-08 にWeb版の実物で確認）
**Zaimには締め日・支払日・引き落とし口座・次回引き落とし予定額の設定も表示も無い。** AIDEのスクレイパーを足しても取れない。
- 口座の編集画面（`https://zaim.net/accounts/<id>`）のフォームは `account[name]`・`account[color]`・`account[balance]`・
  アイコンだけ（`/accounts/<id>/edit` は404）。カード口座でも同じ
- 連携設定（`/online_accounts`）の口座ごとのメニューは「連携データを更新・ログイン情報を修正・公式サイトに移動・連携を解除」だけ
- ホーム（`/home`）の残高一覧もカードは現在の残高だけで、請求予定額は出ない
- スマホアプリの口座設定画面は subpc から開けないため見ていない

**代わりに、引き落とし日と引き落とし口座は家計簿の振替から推定できる。** 連携した銀行の明細は、カードの引き落としを
「銀行 → カード」の振替（`place` が `口座振替 楽天カードサービス`・`口座振替JCB カード` など）として返し、
`lib/ledger-sources/zaim/adapter.ts` が `TRANSFER` として口座の組ごと家計簿へ同期している。AIDE側の変更は要らない。
- 2026年6〜10月の実データでは、カードごとに毎月1回、同じ引き落とし口座からの振替があり、日付は
  「名目の引き落とし日を翌営業日へ送った日」と一致した（例: 27日払いが 6/29・9/28、10日払いが 10/13（10/12がスポーツの日））。
  したがって名目の日は `lib/jp-holidays.ts` の翌営業日送りを逆にたどって決められる
- **締め日と引き落とし月（`paymentMonthOffset`）は振替からは決まらない。** 振替の額とカードの利用の累計を突き合わせれば
  候補は絞れるが、確度は低い。手入力のまま残す
- カードを持っていても引き落としの振替が届かない（引き落とし口座が連携されていない・利用が無い）カードは推定できない
- 振替履歴から初期値を提案する実装は #1157

## 引き落とし額の算出（推計。確定請求額ではない）
- サイクル: 締め日の月から、引き落とし月（当月・翌月・翌々月）の引き落とし日までを1サイクルとする。
  29〜31日は月末に丸める。引き落とし日が休日・年末年始なら翌営業日へ送る（`lib/jp-holidays.ts`）
- 額 = 締め日時点のカード残高の負債額 − 締め日の翌日から今日までのカード口座への入金（繰上げ返済・引き落とし済み分）。
  カードの残高は累積なので、窓の中の複数サイクルは先のサイクルの額を引いて二重に数えない
- 締め日がまだ先のサイクルは、今ある取引までで数える（これから使う分は含まない）
- 判定: 引き落とし口座の今の残高 − それ以前（同日を含む）の引き落とし予定の合計。負なら不足、1万円未満ならぎりぎり。
  将来の入金（給与など）は見込まない。同じ口座・同じ日は合算する

## 口座の削除・統合・全削除
自己参照FK（`withdrawalAccountId`）は、Prisma の制約で `onDelete: NoAction`（`SetNull` は schema の検証で弾かれる）。
そのため `lib/ledger-service.ts` が先に外す: 削除は引き落とし設定ごと外す、統合は結合先へ付け替える
（結合先が自分自身を指すなら外す）、全削除は `updateMany` で外してから `deleteMany`。
