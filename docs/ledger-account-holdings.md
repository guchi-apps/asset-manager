# 家計簿の口座と資産カテゴリの結び付け（Issue #970）

証券口座（SBI 証券・bitFlyer・確定拠出年金など）は、次の2か所にある（#964 の調査）。

- 資産: 銘柄ごとのカテゴリに評価額を記録する（取得原価・リバランス・資産推移の土台）
- 家計簿: 口座として持ち、Zaimの評価額を残高として出す（#881）

方針は「家計簿の口座に寄せる」。資産側の銘柄ごとの評価額は消さず、**どのカテゴリがどの口座の中身か**を結び付ける。
純粋な関数は `lib/ledger-account-holdings.ts`。

## 持ち方

- カテゴリ側に口座を持つ: `Category.ledgerAccountId Int?`（外部キーは張らない）。1つの口座に複数のカテゴリがぶら下がる
- 以前の `LedgerAccount.assetCategoryId`（口座→カテゴリを1つ）はマイグレーション
  `20261118120000_category_ledger_account` でカテゴリ側へ写して削除した。同じカテゴリを複数の口座が指していたときは
  表示中の口座→`order`→`id` の先頭を採った（旧来の用途の判定と同じ順）
- カテゴリが属する口座は、**自分か最も近い祖先の結び付け**（`resolveCategoryAccounts`）。親カテゴリを結び付ければ子も中身になり、
  子に別の結び付けがあれば子が優先する。親子は資産クラスのまとめ（「個別株→A社株式」）にも使われているので、
  口座ごとに親を作らせる形にはしていない
- 1つのカテゴリは1つの口座の中身。口座の編集で別の口座のカテゴリを選ぶと、保存時にその口座へ移る（`linkAssetCategories`）
- 口座を削除すると結び付けは外れる（評価額の記録は残る）。家計簿を丸ごと消すとき（`deleteAllLedgerData`）も外す

## 使い道

- 用途の判定（`lib/account-purpose.ts`・`docs/account-purpose.md`）
- 口座の残高の横に「中身N件の評価額」を出す。残高は従来どおりZaimの評価額（#881）で、中身の合計との差は預り金などにあたる。
  評価額は葉のカテゴリの最新の1件（子を持つカテゴリ自身の記録は数えない。`lib/map-categories.ts` と同じ）
- 初期残高の候補: 選んだカテゴリを葉に広げ、カテゴリごとに基準日の前日以前で最新の評価額を足す。
  記録日はカテゴリごとに揃わないので、最古〜最新の記録日を出す

## 「Zaimの残高に合わせる」の対象外

証券口座（`kind = SECURITIES`）と用途が投資の口座は、Zaimの評価額と家計簿の計算に差があっても合わせない
（`isExcludedFromReconcile`）。差は含み損益で、合わせると値動きが初期残高や残高調整の取引として家計簿へ入るため。
画面の一覧（`planExternalReconciliation`）から外し、サーバー側（`reconcileAccountBalances`）でも断る。
口座のカードには「家計簿の計算との差」も出さない。
