# Zaimで振替にまとめられた明細の片付け（#1379）

## 起きること

ICOCAへのチャージ（モバイルICOCA・カード払い）は、Zaimへ次の順で届く。

1. 先にICOCAの入金（収入「チャージ」¥10,000、入金先ICOCA）が届く → 家計簿の取り込みで**収入の取引**になる
2. あとでカードの利用（OSC J-WEST の ¥10,000）が届く
3. Zaimが1と2を**1件の振替（OSC J-WEST → ICOCA）**へ自動でまとめる。1の収入はZaimから消える

家計簿には振替が新しい明細として届き、1の収入は「見当たらない」になる。何もしないと、ICOCAへの入金が
振替と収入で**二重に**数えられる（要対応に「Zaimで見当たりません」と出ていた）。

## 取り回し

取り込み（`lib/ledger-sources/sync-service.ts` の `dismissMergedIntoTransfer`）で、見当たらなくなった収入・支出が
振替へまとめられたものと判断できれば、**元の取引を削除して記録を確認済み（`DISMISSED`）にする**。取り込み結果には
「振替にまとめられた N件」と、明細ごとに「Zaimで振替にまとめられたため、二重に数えないよう取引を削除しました」が残る。

まとめられたと判断する条件（`lib/ledger-sources/sync-plan.ts` の `pickMergedIntoTransfer`）:

- 見当たらない明細が収入なら入金先、支出なら出金元の口座が、振替の同じ側の口座と対応表で一致する
- 金額が同じで、日付のずれが `TRANSFER_MERGE_WINDOW_DAYS`（3日）以内
- 振替が、見当たらない明細が最後に見えた**あとで初めて**届いた（2つが同時にZaimにあったことが無い）。
  毎月同じ額の振替が以前からある、といった無関係な振替と組にしないため
- 候補の振替がちょうど1件で、同じ振替の同じ側へ当たる明細も1件だけ
- 振替が取引になっている（情報源の口座の振替なら、元の取引を消すと入金そのものが消える）

次の取引は自動では消さず、従来どおり「見当たらない」として要対応に回す。

- 家計簿で手直しした取引（`editedFields` がある）
- レシート・立替・支払いの分割を結び付けた取引

カードの利用（支出）が先に取引になってから振替へまとめられた場合も、同じ条件で支出側を片付ける。

## 判断の記録

- **自動で片付ける**ことにした（Issue #1379 で決定）。要対応に案内だけ出す案、分類ルール「振替の受け側」で
  チャージ収入を取引にしない運用案も検討したが、前者は毎回の手作業が残り、後者はカードの利用が届くまで
  ICOCAの残高が合わないうえ、ルールが口座を条件にできないため見送った
- 対象は今回の取り込みで新たに「見当たらない」になる明細だけ。すでに「見当たらない」になっている明細は、
  要対応の「取引を削除」で片付ける
- 片付けた明細があとでZaimに戻ってきたら、ほかの「見当たらない」明細と同じく取引を作り直す
